# rag-eval-lab

Retrieval-augmented generation with a measurable retrieval layer. Markdown documents are chunked, indexed in
Postgres/pgvector (or in memory), searched with **vector**, **keyword** and **hybrid (Reciprocal Rank Fusion)** retrieval,
and evaluated with hit@k and MRR. Answers are generated by a local Ollama model with citations that are checked mechanically.

## The problem
RAG quality is usually judged by reading a few answers. This project separates retrieval from generation and scores
each retrieval strategy on a labelled question set, so changes to chunking, embeddings or search mode can be compared with numbers.

## Features
- Markdown-aware chunking: heading kept as metadata, word windows with overlap, frontmatter metadata
- Embedders: Ollama `nomic-embed-text` (with its `search_document:` / `search_query:` prefixes) or an offline deterministic hashing embedder for tests and CI
- Two interchangeable stores: `pgvector` (HNSW cosine index + GIN full-text index) and an in-memory store (numpy + BM25)
- Three retrieval modes; hybrid fuses the vector and keyword rankings with RRF (k = 60)
- Metadata filtering (`--category billing`)
- Grounded answers with `[n]` citations; citations that point at non-existent sources are flagged
- Evaluation harness: hit@1/3/5 and MRR per retrieval mode on a hand-labelled question set (22 questions, 21 chunks)
- 13 pytest tests, including pgvector integration tests when a database is available

## Architecture
```
data/corpus/*.md -> chunking.py -> Chunk(id, source, heading, text, metadata)
                                      |  embedders.py (Ollama | hashing)
                                      v
                          stores.py: MemoryStore | PgVectorStore
                              |  vector_search     |  keyword_search
                              v                    v
                      retrieval.py:  vector | keyword | hybrid = rrf_fuse(both)
                              |
              +---------------+----------------+
              v                                v
        evaluate.py (hit@k, MRR)       generate.py (prompt + citation check)
```

## Key technical decisions
- **Fusion in Python over ranked ID lists.** RRF works with any store and is unit-testable, instead of living in one SQL statement.
- **OR-ed full-text query.** Natural-language questions rarely contain only words that all appear in one chunk, so terms are OR-ed (`to_tsquery`) rather than AND-ed (`plainto_tsquery`).
- **Relevance is judged at source (and heading, when labelled) level**, not by exact chunk, so labels stay valid when chunking changes.
- **One store interface** (`MemoryStore` / `PgVectorStore`), so evaluation results are comparable across backends.
- **Mechanical citation check** instead of trusting the model to cite correctly.

## How to run
```bash
pip install -e ".[dev]"
python -m pytest                               # no services needed (the pgvector test is skipped)
python -m rag_eval_lab eval                    # offline: in-memory store + hashing embedder
python -m rag_eval_lab search "how long do refunds take" --mode hybrid
```
With Postgres (`docker compose up -d`) and Ollama (`ollama pull nomic-embed-text llama3.2`):
```bash
cp .env.example .env && export $(grep -v '^#' .env | xargs)
python -m rag_eval_lab eval --store pgvector --embedder ollama
python -m rag_eval_lab ask "Can I return a gift card?" --store pgvector --embedder ollama --category billing
TEST_DATABASE_URL=$DATABASE_URL python -m pytest   # also runs the pgvector test
```

## Example output
Offline run with the hashing embedder:
```
21 chunks, 22 questions, embedder=hashing, store=memory

mode       hit@1   hit@3   hit@5     mrr
vector      0.36    0.64    0.77    0.52
keyword     0.73    0.91    0.91    0.80
hybrid      0.64    0.77    0.86    0.73
```
The hashing embedder is lexical, not semantic, so these numbers validate the pipeline and the metrics rather than benchmark an embedding model.
Run `eval --embedder ollama` to evaluate semantic retrieval.

## Evaluation
`python -m rag_eval_lab eval` scores every retrieval mode on `data/eval/questions.jsonl`. A hit means a chunk from the expected
source (and heading, when the question specifies one) appears in the top k results; MRR is the mean of 1/rank of the first such chunk.

## Limitations
- The corpus is small (21 fictional support-article chunks) and 22 questions are too few for statistically meaningful comparisons.
- The reported numbers use the offline embedder; the Ollama embedding path is implemented but has no published results.
- The citation check verifies that the cited source exists, not that the claim is supported by it.
- No reranker, no streaming, and the index is rebuilt on every indexing run.
